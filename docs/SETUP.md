# Как запустить бота

Пошаговая инструкция «с нуля». Всё делается один раз, вместе — около часа. Шаги 1–4 (шаг 3 можно пропустить) нужны, чтобы выдать боту доступы: их нельзя сделать за вас, потому что это ваши аккаунты в Telegram и Google. Шаг 5 — где бот будет работать: бесплатно на Railway или на своём сервере.

**Что понадобится**

- аккаунт Telegram с правом добавлять ботов в рабочую группу;
- КП, открытая по ссылке («Все, у кого есть ссылка»); если делаете шаг 3 — аккаунт Google с правом редактировать КП;
- аккаунт на GitHub, чтобы войти в Railway (он у вас есть — вы владелец репозитория), либо свой сервер с Linux и Docker;
- 15 минут внимания команды: предупредить, что бот читает рабочий чат.

> **Про безопасность.** Токен бота и ключ Google — это пароли. Не публикуйте их, не отправляйте в чаты и не коммитьте в репозиторий: репозиторий публичный. Файлы `.env`, `config.yaml`, папка `data/` уже внесены в `.gitignore`. На Railway токен и настройки лежат в разделе Variables вашего проекта — репозиторий их не видит.

## Шаг 1. Создать бота в Telegram

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Придумайте имя (его увидит команда) и username (должен заканчиваться на `bot`).
3. BotFather пришлёт **токен** — строку вида `123456789:AAH…`. Сохраните её: это значение `BOT_TOKEN` в шаге 5.
4. Отправьте BotFather `/setprivacy`, выберите бота и нажмите **Disable**. Так бот сможет видеть обычные сообщения группы, а не только команды. Если бот будет администратором группы (шаг 2), он и так видит всё, но лучше отключить оба ограничения.
5. По желанию: `/setuserpic` и `/setdescription` — картинка и описание.

## Шаг 2. Добавить бота в рабочую группу

1. В группе: «Добавить участника» → найдите бота по username.
2. Сделайте его **администратором** с правом «Закрепление сообщений» — остальные права не нужны. Закреп нужен для «Доски» с постами недели.
3. Предупредите команду: бот читает весь чат, чтобы замечать «беру пост» и смену этапов, но сохраняет только события по постам.

> Если вы поменяли режим приватности **после** добавления бота, удалите бота из группы и добавьте снова: Telegram применяет настройку при добавлении.

## Шаг 3. Доступы Google (можно пропустить)

**Без ключа бот тоже работает.** Если КП открыта по ссылке («Все, у кого есть ссылка»), он скачивает её сам, без всяких ключей: посты, статусы, сроки, напоминания — всё на месте. Теряется немногое: комментарии клиента к ячейкам КП, комментарии в доках и копия трекера в отдельной таблице. Пропустите этот шаг, оставьте `KP_SPREADSHEET_ID` в переменных, а ключ добавьте позже, если понадобятся комментарии. Сервисный аккаунт Google бесплатный, платить не нужно.

Если ключ всё же нужен:

Бот читает КП через сервисный аккаунт — «робота» Google с собственной почтой. Он видит только те файлы, которыми с ним поделились.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/), создайте проект (например, «SMM bot»).
2. **API и сервисы → Библиотека:** найдите и включите **Google Drive API** и **Google Sheets API**.
3. **IAM и администрирование → Сервисные аккаунты → Создать сервисный аккаунт.** Название любое. Роли на проекте назначать не нужно.
4. Откройте созданный аккаунт → вкладка **Ключи → Добавить ключ → Создать новый ключ → JSON.** Скачается файл. Переименуйте его в `service-account.json`. Он подходит только для запуска на своём сервере (шаг 5Б): файл кладётся в папку `data/`.
5. Скопируйте **адрес сервисного аккаунта** (выглядит как `имя@проект.iam.gserviceaccount.com`).
6. **КП:** откройте таблицу → «Настройки доступа» → добавьте этот адрес с правом **«Читатель»**. Бот ничего не пишет в КП, поэтому правка ему не нужна.
   Идентификатор КП — часть ссылки между `/d/` и `/edit`: это `KP_SPREADSHEET_ID`.
7. **Внутренняя таблица (необязательно).** Создайте новую пустую таблицу «Трекер бота» и дайте тому же адресу право **«Редактор».** Бот будет вести в ней копию трекера: полезно, если хочется смотреть всё в таблице. Идентификатор — `TRACKER_SPREADSHEET_ID`. Эту таблицу не показывайте клиенту и не правьте руками: все изменения идут через чат.
8. **Доки с текстами (необязательно).** Чтобы бот замечал комментарии клиента в доках, поделитесь с тем же адресом папкой с доками (право «Читатель»). Без этого бот всё равно читает комментарии в самой КП.

> Если в шаге 6 нельзя добавить адрес (нет права делиться), попросите владельца КП.

## Шаг 4. Подготовить настройки

Настройки — это команда, роли и имена людей клиента. В репозиторий их класть нельзя, поэтому они хранятся там, где работает бот.

1. Возьмите `config.example.yaml` и скопируйте его текст в свой файл (пока на компьютере, например в блокноте).
2. Впишите команду: имя, username без `@`, роль (`copywriter`, `responsible`, `boss`).
3. Впишите в `client_names` имена людей клиента, как их называют в чате («отправил Алисе текст»), — так бот поймёт, что текст ушёл клиенту. Слова «клиент» и «заказчик» понимаются и без списка.
4. Впишите в `client_authors` и `team_authors` имена авторов комментариев так, как их показывает Google — откройте любой комментарий в КП и посмотрите, как подписан автор. Ошибиться не страшно: автор, которого нет в `team_authors`, считается клиентом.
5. `chat_id` пока оставьте как есть — вы узнаете его после первого запуска (шаг 6).
6. Что делать с готовым текстом:
   - **Railway (5А):** целиком вставить в переменную `CONFIG_YAML` — файл не нужен;
   - **свой сервер (5Б):** сохранить как `data/config.yaml`.

## Шаг 5. Где будет работать бот

Бот должен быть включён круглосуточно: он слушает чат и напоминает о сроках. Есть два пути.

| | Railway | Свой сервер |
|---|---|---|
| Цена | бесплатно (тариф Free, кредит $1 в месяц; боту нужно около $0,6) | от 200–400 ₽ в месяц за VPS |
| Что нужно | аккаунт GitHub, 15 минут | сервер с Linux и Docker, терминал |
| Сложность | всё мышкой в браузере | команды в терминале |
| Оговорки | условия тарифа могут поменяться; на бесплатном тарифе нет резервных копий базы | самому обновлять и следить |

Сервер должен быть за границей: с российских адресов Telegram в 2026 году работает с перебоями. Railway — зарубежный сервис, оттуда Telegram открывается нормально.

### Вариант А. Railway (бесплатно, свой сервер не нужен)

**Сколько это стоит.** Railway считает расход по факту: за память $10 за ГБ в месяц, за процессор $20 за ядро в месяц. Новому аккаунту дают пробные $5 на 30 дней, потом он переходит на тариф Free: $0 в месяц и $1 кредита на расход, карту для этого не просят. Бот занимает 50–60 МБ памяти, то есть около $0,6 в месяц, — в кредит укладывается. Если кредит всё же закончится раньше конца месяца, Railway остановит бота до следующего месяца (тогда в чате появится «Меня не было…»). Расход виден на странице Usage; проверьте её через несколько дней после запуска. Если запаса не хватит, есть платный тариф Hobby ($5 в месяц, нужна банковская карта, которая принимается Railway) или свой сервер (вариант Б). Актуальные условия — на [railway.com/pricing](https://railway.com/pricing).

Названия кнопок в Railway могут немного отличаться от тех, что ниже, — ориентируйтесь на смысл.

1. **Аккаунт.** Откройте [railway.com](https://railway.com), нажмите «Login» и войдите через GitHub — тем аккаунтом, которому принадлежит репозиторий. Если вы уже пользовались Railway, войдите в тот же аккаунт: посмотрите в его настройках, какой у вас тариф (Trial, Free или Hobby).
2. **Проект.** «New Project» → «Deploy from GitHub repo» → выберите `norm_tasker`. Если репозитория в списке нет, нажмите «Configure GitHub App» и разрешите Railway доступ к нему.
3. **Ветка.** Откройте созданный сервис → «Settings» → «Source» → выберите ветку `claude/smm-telegram-bot-plan-pcb17p` (пока код не влит в основную). Файл `railway.toml` в репозитории уже говорит Railway, что собирать из Dockerfile и перезапускать бота при любой остановке. Дальше каждое обновление этой ветки Railway применит сам.
4. **Переменные.** В сервисе откройте «Variables» и добавьте:

   | Имя | Что вписать |
   |---|---|
   | `BOT_TOKEN` | токен из шага 1 |
   | `KP_SPREADSHEET_ID` | идентификатор КП: часть ссылки между `/d/` и `/edit` |
   | `CONFIG_YAML` | весь текст настроек из шага 4, с переносами строк |
   | `CHAT_ID` | пока не нужно — добавите в шаге 6 |
   | `TRACKER_SPREADSHEET_ID` | только если делали шаг 3.7 |

   Если при вставке многострочного текста в `CONFIG_YAML` пропали переносы строк, закодируйте его в base64 и вставьте одной строкой в переменную `CONFIG_B64` (вместо `CONFIG_YAML`). Закодировать можно командой `python -c "import base64;print(base64.b64encode(open('config.yaml','rb').read()).decode())"`, а можно попросить помощника подготовить строку.
5. **Диск для базы.** Подключите к сервису том (Volume) с путём монтирования `/data`: правый клик по сервису на схеме проекта → «Attach Volume» (или кнопка «+ New» → «Volume»). Без тома база сотрётся при каждом перезапуске, и бот забудет, кто что взял. Тома на бесплатном тарифе — до 0,5 ГБ, базе этого хватает с запасом.
6. **Запуск.** Нажмите «Deploy» (Railway предложит применить накопленные изменения). Сборка займёт пару минут. Откройте «Deployments» → «View logs»: в журнале должна появиться строка «Бот @имя запущен».
7. Не включайте в настройках сервиса «Serverless» (он усыпляет сервис) — бот должен работать без перерыва.

Дальше — шаг 6.

### Вариант Б. Свой сервер (VPS) или компьютер

Подойдёт любой VPS с Ubuntu 22.04+ (512 МБ памяти достаточно). Сервер должен открывать сайты `api.telegram.org` и `googleapis.com`.

```bash
# установить Docker (один раз)
curl -fsSL https://get.docker.com | sh

# забрать код бота
git clone https://github.com/kazaeza/norm_tasker.git
cd norm_tasker
git checkout claude/smm-telegram-bot-plan-pcb17p   # пока ветка не влита в основную
mkdir -p data
```

Если репозиторий сделают приватным, `git clone` попросит вход в GitHub: используйте личный токен доступа (Settings → Developer settings → Personal access tokens) вместо пароля.

Если пробуете на своём компьютере: установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и выполните то же самое в терминале.

**Первый запуск.**

1. Создайте файл `.env` рядом с `docker-compose.yml`: скопируйте `.env.example` и впишите
   `BOT_TOKEN` (шаг 1), `KP_SPREADSHEET_ID` и, если делали шаг 3.7, `TRACKER_SPREADSHEET_ID`.
2. Положите в `data/` файл `config.yaml` (шаг 4) и, если делали шаг 3, `service-account.json`.
3. Проверьте настройки — бот сам скажет, чего не хватает:

   ```bash
   docker compose run --rm bot python -m norm_tasker doctor
   ```

   Пункты с ✅ в порядке, с ❌ — исправьте по подсказке рядом. `chat_id` на этом этапе можно не заполнять.
4. Запустите:

   ```bash
   docker compose up -d --build
   docker compose logs -f      # смотреть журнал; выйти — Ctrl+C, бот продолжит работать
   ```

## Шаг 6. Узнать chat_id и включить бота в чате

1. В рабочей группе отправьте `/id`. Бот ответит номером чата (`chat_id`, вида `-100…`) и покажет, кем вы записаны в настройках.
   Если в группе включены темы и бот должен писать в одну из них — отправьте `/id` **в этой теме** и возьмите `thread_id`.
2. Сообщите боту номер чата:
   - **Railway:** добавьте в Variables переменную `CHAT_ID` (а при темах — и `THREAD_ID`). Railway перезапустит бота сам.
   - **Свой сервер:** впишите `chat_id` (и `thread_id`) в `data/config.yaml` и перезапустите: `docker compose restart`.
3. Свой сервер: ещё раз запустите `doctor` — теперь он проверит и права бота в чате.
4. В чате отправьте `/status`: бот покажет, когда последний раз читал КП и есть ли предупреждения.

## Шаг 7. Начать пользоваться

1. Ответственный за проект отправляет `/inventory`: бот выкладывает посты на две недели и просит отметить, кто что делает и на каком этапе. Так трекер сразу отражает реальное положение дел.
2. `/board` — опубликовать и закрепить доску. Дальше бот обновляет её сам.
3. Команда пишет в чат как обычно: «беру пост на пятницу», «текст готов, отправил клиенту», «клиент ок по тексту», «отдал дизайнеру», «дизайн готов», «показал клиенту с дизайном», «финальный ок», «вышел». Любое действие можно отменить кнопкой или `/undo`.
4. **Мягкий старт.** Первые 14 дней бот только пишет утреннее саммари и ведёт доску, без напоминаний и эскалаций. Срок меняется в `soft_start_days`. За это время станет видно, где бот ошибается, — сообщите, поправим.
5. Полный список фраз и команд — `/help`.

## Обновление и резервные копии

**Railway.** Код обновляется сам: как только в выбранной ветке появляется новая версия, Railway пересобирает бота и перезапускает его (на пару минут бот замолкает, накопившиеся сообщения он прочитает после запуска — Telegram хранит их сутки). Вся память бота лежит на томе `/data`. На бесплатном тарифе автоматических копий тома нет, а если кредит закончится и тариф не сменить, Railway удалит том через 30 дней после остановки. Потерянную базу можно восстановить не полностью: этапы подтянутся из статусов КП, остальное восстановит команда `/inventory`.

**Свой сервер.**

```bash
cd norm_tasker
git pull
docker compose up -d --build
```

Вся память бота — файл `data/tracker.db`. Копируйте его время от времени (например, раз в неделю), вместе с `data/config.yaml`.

## Если что-то не работает

| Что видите | Что делать |
|---|---|
| `doctor` пишет «КП недоступно … не расшарен» | Откройте КП по ссылке для всех («Все, у кого есть ссылка») или поделитесь ею с адресом сервисного аккаунта (шаг 3.6). Адрес виден в первой строке `doctor`. |
| `doctor` пишет «не включён API» | Включите Drive API и Sheets API в проекте Google Cloud (шаг 3.2), подождите минуту. |
| Бот не реагирует на «беру» | Отправьте `/status` и `/id`. Если `/id` отвечает, а «беру» нет — проверьте, что бот администратор и режим приватности выключен (шаг 1.4, 2). Если `/id` не отвечает — бот не запущен или неверный `BOT_TOKEN`: смотрите журнал (Railway: Deployments → View logs; Docker: `docker compose logs`). |
| В журнале «Telegram не принял токен бота» | Проверьте `BOT_TOKEN`: без пробелов, кавычек и лишних символов. Токен можно перевыпустить у @BotFather командой `/revoke`. |
| В журнале «Ошибка настроек» | Текст в `CONFIG_YAML` или `config.yaml` не по образцу `config.example.yaml`: журнал называет строку или поле с ошибкой. |
| Бот отвечает только на `/id` | Не указан `chat_id` (шаг 6). |
| Railway: журнал полон строк «Telegram пока недоступен» | Подключите GitHub-аккаунт в настройках Railway: у непроверенного пробного аккаунта закрыт исходящий доступ в сеть. |
| Railway: бот остановился посреди месяца | Закончился бесплатный кредит ($1). Расход виден на странице Usage. Дождитесь следующего месяца, перейдите на тариф Hobby или запустите бота на своём сервере. |
| Доска не закрепляется | Дайте боту право «Закрепление сообщений». |
| Реакции 👍 не ставятся | В группе ограничены реакции. Бот в таком случае пишет «👍 Записал.» текстом — ничего делать не нужно. |
| «Мог что-то пропустить» после простоя | Telegram хранит сообщения для бота 24 часа. Сверьте доску (`/board`) и поправьте этапы. |
| Бот принял заметку за пост | Ответьте на его сообщение «не пост». Заметки лучше начинать с «NB:» — такие строки в КП бот пропускает. |
| Пост не тот | Нажмите «Отменить» под ответом бота или `/undo`. |

Проблему, которой здесь нет, можно диагностировать по журналу: на Railway — Deployments → View logs, в Docker — `docker compose logs --tail 200`. Приложите вывод, когда будете писать разработчику (токен и ключи в журнал не попадают).

## Как проверить КП без запуска бота

Если хочется убедиться, что бот правильно разбирает таблицу и считает сроки:

1. В Google Таблицах: **Файл → Скачать → Microsoft Excel (.xlsx).**
2. Выполните (нужен Python 3.12 и `pip install .`):

   ```bash
   python -m norm_tasker parse выгрузка.xlsx --weeks 3
   ```

   Команда покажет посты, рубрики, статусы, этапы и сроки. Файл остаётся на вашем компьютере.
