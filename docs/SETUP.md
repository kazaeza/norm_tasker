# Как запустить бота

Пошаговая инструкция «с нуля». Всё делается один раз, вместе — около часа. Шаги 1–4 (шаг 3 можно пропустить) нужны, чтобы выдать боту доступы: их нельзя сделать за вас, потому что это ваши аккаунты в Telegram и Google. Шаг 5 — где бот будет работать: в облаке Amvera (от 170 ₽ в месяц, всё мышкой в браузере) или на своём сервере.

**Что понадобится**

- аккаунт Telegram с правом добавлять ботов в рабочую группу;
- КП, открытая по ссылке («Все, у кого есть ссылка»); если делаете шаг 3 — аккаунт Google с правом редактировать КП;
- аккаунт в Amvera Cloud и банковская карта РФ, чтобы пополнить баланс (170–290 ₽ в месяц), либо свой сервер с Linux и Docker;
- аккаунт на GitHub (он у вас есть — вы владелец репозитория): нужен, только чтобы обновления бота подтягивались в Amvera сами;
- 15 минут внимания команды: предупредить, что бот читает рабочий чат.

> **Про безопасность.** Токен бота и ключ Google — это пароли. Не публикуйте их, не отправляйте в чаты и не коммитьте в репозиторий: репозиторий публичный. Файлы `.env`, `config.yaml`, папка `data/` уже внесены в `.gitignore`. В Amvera токен и настройки лежат в разделе «Переменные» вашего проекта — репозиторий их не видит.

---

## Шаг 1. Создать бота в Telegram

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Придумайте имя (его увидит команда) и username (должен заканчиваться на `bot`).
3. BotFather пришлёт **токен** — строку вида `123456789:AAH…`. Сохраните её: это значение `BOT_TOKEN` в шаге 5.
4. Отправьте BotFather `/setprivacy`, выберите бота и нажмите **Disable**. Так бот сможет видеть обычные сообщения группы, а не только команды. Если бот будет администратором группы (шаг 2), он и так видит всё, но лучше отключить оба ограничения.
5. По желанию: `/setuserpic` и `/setdescription` — картинка и описание.

## Шаг 2. Добавить бота в рабочую группу

1. В группе: «Добавить участника» → найдите бота по username.
2. Сделайте его **администратором** с правом «Закрепление сообщений» — остальные права не нужны. Закреп нужен для «Доски» с постами недели.
3. Предупредите команду: бот читает весь чат, чтобы замечать «беру пост» и смену этапов, но сохраняет только события по постам.

> Если вы поменяли режим приватности **после** добавления бота, удалите бота из группы и добавьте снова: Telegram применяет настройку при добавлении.

## Шаг 3. Доступы Google (можно пропустить)

**Без ключа бот тоже работает.** Если КП открыта по ссылке («Все, у кого есть ссылка»), он скачивает её сам, без всяких ключей: посты, статусы, сроки, напоминания — всё на месте. Теряется немногое: комментарии клиента к ячейкам КП, комментарии в доках и копия трекера в отдельной таблице. Пропустите этот шаг, оставьте `KP_SPREADSHEET_ID` в переменных, а ключ добавьте позже, если понадобятся комментарии. Сервисный аккаунт Google бесплатный, платить не нужно.

Если ключ всё же нужен:

Бот читает КП через сервисный аккаунт — «робота» Google с собственной почтой. Он видит только те файлы, которыми с ним поделились.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/), создайте проект (например, «SMM bot»).
2. **API и сервисы → Библиотека:** найдите и включите **Google Drive API** и **Google Sheets API**.
3. **IAM и администрирование → Сервисные аккаунты → Создать сервисный аккаунт.** Название любое. Роли на проекте назначать не нужно.
4. Откройте созданный аккаунт → вкладка **Ключи → Добавить ключ → Создать новый ключ → JSON.** Скачается файл. Переименуйте его в `service-account.json`. Файл кладётся в папку данных бота: на своём сервере (шаг 5Б) — в `data/`, в Amvera — в папку Data проекта (загрузка файлов в неё открывается в интерфейсе после первого успешного запуска).
5. Скопируйте **адрес сервисного аккаунта** (выглядит как `имя@проект.iam.gserviceaccount.com`).
6. **КП:** откройте таблицу → «Настройки доступа» → добавьте этот адрес с правом **«Читатель»**. Бот ничего не пишет в КП, поэтому правка ему не нужна.
   Идентификатор КП — часть ссылки между `/d/` и `/edit`: это `KP_SPREADSHEET_ID`.
7. **Внутренняя таблица (необязательно).** Создайте новую пустую таблицу «Трекер бота» и дайте тому же адресу право **«Редактор».** Бот будет вести в ней копию трекера: полезно, если хочется смотреть всё в таблице. Идентификатор — `TRACKER_SPREADSHEET_ID`. Эту таблицу не показывайте клиенту и не правьте руками: все изменения идут через чат.
8. **Доки с текстами (необязательно).** Чтобы бот замечал комментарии клиента в доках, поделитесь с тем же адресом папкой с доками (право «Читатель»). Без этого бот всё равно читает комментарии в самой КП.

> Если в шаге 6 нельзя добавить адрес (нет права делиться), попросите владельца КП.

## Шаг 4. Подготовить настройки

Настройки — это команда, роли и имена людей клиента. В репозиторий их класть нельзя, поэтому они хранятся там, где работает бот.

1. Возьмите `config.example.yaml` и скопируйте его текст в свой файл (пока на компьютере, например в блокноте).
2. Впишите команду: имя, username без `@`, роль (`copywriter`, `responsible`, `boss`).
3. Впишите в `client_names` имена людей клиента, как их называют в чате («отправил Алисе текст»), — так бот поймёт, что текст ушёл клиенту. Слова «клиент» и «заказчик» понимаются и без списка.
4. Впишите в `client_authors` и `team_authors` имена авторов комментариев так, как их показывает Google — откройте любой комментарий в КП и посмотрите, как подписан автор. Ошибиться не страшно: автор, которого нет в `team_authors`, считается клиентом.
5. `chat_id` пока оставьте как есть — вы узнаете его после первого запуска (шаг 6).
6. Что делать с готовым текстом:
   - **Amvera (5А):** закодировать в одну строку (base64) и вставить в переменную `CONFIG_B64` — файл не нужен;
   - **свой сервер (5Б):** сохранить как `data/config.yaml`.

## Шаг 5. Где будет работать бот

Бот должен быть включён круглосуточно: он слушает чат и напоминает о сроках. Полностью бесплатного варианта без подвохов не нашлось: в сентябре 2026 проверены Railway, Render, Fly.io, Koyeb, Zeabur, Back4app, Northflank, Cloudflare Workers, Hugging Face и alwaysdata. У одних нет бесплатного тарифа для новых аккаунтов, другие засыпают или стирают файлы, третьи требуют зарубежную банковскую карту. Остались два пути.

| | Amvera Cloud | Свой сервер |
|---|---|---|
| Цена | 170 ₽ в месяц (тариф Trial) или 290 ₽ (Starter); новым пользователям дают 111 ₽ на пробу | от 500 ₽ в месяц за VPS за границей |
| Оплата | карта РФ, предоплата | зависит от провайдера |
| Что нужно | e-mail, карта РФ, 20 минут | сервер с Linux и Docker, терминал |
| Сложность | всё мышкой в браузере | команды в терминале |
| Резервные копии базы | раз в сутки, делает Amvera | самому |

Сервер должен быть за границей: с российских адресов Telegram в 2026 году открывается с перебоями. У Amvera для этого есть зона размещения «Варшава».

### Вариант А. Amvera Cloud (российский сервис, оплата картой РФ)

**Сколько это стоит.** Amvera работает по предоплате: вы пополняете баланс, а деньги списываются понемногу, по часам. Тариф Trial — 170 ₽ за 30 дней и 100 МБ памяти: боту нужно около 50 МБ, так что должно хватить. Тариф Starter — 290 ₽ за 30 дней, 500 МБ памяти и в 2,5 раза больше процессора: переходите на него, если Trial окажется тесным (проект перезапускается сам или отвечает с большой задержкой). Тариф можно менять в любой момент. Приветственных 111 ₽ хватит на пару недель проб. Российские карты принимаются без ограничений. Если баланс дойдёт до нуля, проект остановится, а через 30 дней заморозится, поэтому следите за балансом или включите автоплатёж. Актуальные цены — на [docs.amvera.ru](https://docs.amvera.ru/general/price.html).

Названия кнопок в Amvera могут немного отличаться от тех, что ниже, — ориентируйтесь на смысл.

1. **Аккаунт.** Откройте [cloud.amvera.ru](https://cloud.amvera.ru) и зарегистрируйтесь.
2. **Проект.** «Создать проект» → тип «Приложение» → имя (например, `norm-tasker`) → тариф Trial → зона размещения **«Варшава»**. Из зоны «Москва» бот не достучится до Telegram.
3. **Код.** Подключите GitHub и ничего не загружайте руками: файлы, загруженные вручную, создают в Amvera собственную историю, она расходится с GitHub, и после этого обновления перестают доходить.
   - Откройте вкладку «Репозиторий», найдите блок «Подключить GitHub, GitLab, Bitbucket» и вкладку GitHub. В поле «Токен» вставьте токен GitHub (кнопка «Сгенерировать» подскажет, как его создать; ему нужны доступы Contents и Webhooks к репозиторию `norm_tasker`). Выберите «Удалённый репозиторий» — `norm_tasker`, «Ветка» — `claude/smm-telegram-bot-plan-pcb17p` (пока код не влит в основную) и сохраните.
   - Папка Code останется пустой, пока в ветку не придёт первое обновление: сборка стартует от пуша. Напишите помощнику, что подключили, — он сделает пуш, и Amvera соберёт бота. Дальше каждое обновление ветки собирается само.
   - Если GitHub вам не нужен, код можно отправить по-другому: скачайте [архив ветки](https://github.com/kazaeza/norm_tasker/archive/refs/heads/claude/smm-telegram-bot-plan-pcb17p.zip), распакуйте его (сам архив загружать нельзя) и перетащите на вкладку «Репозиторий» файлы `Dockerfile`, `amvera.yaml`, `pyproject.toml`, `README.md` и папку `src`. Тогда GitHub подключать не нужно, а при каждом обновлении кода файлы придётся загружать заново.
4. **Переменные.** Откройте «Переменные» и добавьте:

   | Имя | Что вписать |
   |---|---|
   | `BOT_TOKEN` | токен из шага 1; добавляйте как секрет (значение будет скрыто) |
   | `KP_SPREADSHEET_ID` | идентификатор КП: часть ссылки между `/d/` и `/edit` |
   | `CONFIG_B64` | настройки из шага 4, закодированные в одну строку (ниже) |
   | `CHAT_ID` | пока не нужно — добавите в шаге 6 |
   | `TRACKER_SPREADSHEET_ID` | только если делали шаг 3.7 |

   Значение переменной — одна строка, поэтому многострочный текст настроек надёжнее закодировать в base64. Закодировать можно командой `python -c "import base64;print(base64.b64encode(open('config.yaml','rb').read()).decode())"`, а можно попросить помощника подготовить строку. Если поле принимает многострочный текст, можно вместо этого вставить сам YAML в переменную `CONFIG_YAML`. Amvera применяет переменные только после перезапуска проекта.
5. **Запуск.** Когда код загружен, Amvera сама соберёт образ и запустит бота — это занимает несколько минут. Журнал открывается на вкладке «Логи»: в нём должна появиться строка «Бот @имя запущен». Пока запуск не завершился, статус может быть «Ошибка работы приложения» — в первые минуты это нормально. Папка `/data` подключена к проекту автоматически (её задаёт `amvera.yaml`): в ней лежит база бота, и Amvera сохраняет её между запусками.

Дальше — шаг 6.

### Вариант Б. Свой сервер (VPS) или компьютер

Подойдёт любой VPS с Ubuntu 22.04+ (512 МБ памяти достаточно). Сервер должен быть за границей и открывать сайты `api.telegram.org` и `googleapis.com`.

```bash
# установить Docker (один раз)
curl -fsSL https://get.docker.com | sh

# забрать код бота
git clone https://github.com/kazaeza/norm_tasker.git
cd norm_tasker
git checkout claude/smm-telegram-bot-plan-pcb17p   # пока ветка не влита в основную
mkdir -p data
```

Если репозиторий сделают приватным, `git clone` попросит вход в GitHub: используйте личный токен доступа (Settings → Developer settings → Personal access tokens) вместо пароля.

Если пробуете на своём компьютере: установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и выполните то же самое в терминале.

**Первый запуск.**

1. Создайте файл `.env` рядом с `docker-compose.yml`: скопируйте `.env.example` и впишите
   `BOT_TOKEN` (шаг 1), `KP_SPREADSHEET_ID` и, если делали шаг 3.7, `TRACKER_SPREADSHEET_ID`.
2. Положите в `data/` файл `config.yaml` (шаг 4) и, если делали шаг 3, `service-account.json`.
3. Проверьте настройки — бот сам скажет, чего не хватает:

   ```bash
   docker compose run --rm bot python -m norm_tasker doctor
   ```

   Пункты с ✅ в порядке, с ❌ — исправьте по подсказке рядом. `chat_id` на этом этапе можно не заполнять.
4. Запустите:

   ```bash
   docker compose up -d --build
   docker compose logs -f      # смотреть журнал; выйти — Ctrl+C, бот продолжит работать
   ```

## Шаг 6. Узнать chat_id и включить бота в чате

1. В рабочей группе отправьте `/id`. Бот ответит номером чата (`chat_id`, вида `-100…`) и покажет, кем вы записаны в настройках.
   Если в группе включены темы и бот должен писать в одну из них — отправьте `/id` **в этой теме** и возьмите `thread_id`.
2. Сообщите боту номер чата:
   - **Amvera:** добавьте в «Переменные» переменную `CHAT_ID` (а при темах — и `THREAD_ID`) и перезапустите проект: переменные применяются только после перезапуска.
   - **Свой сервер:** впишите `chat_id` (и `thread_id`) в `data/config.yaml` и перезапустите: `docker compose restart`.
3. Свой сервер: ещё раз запустите `doctor` — теперь он проверит и права бота в чате.
4. В чате отправьте `/status`: бот покажет, когда последний раз читал КП и есть ли предупреждения.

## Шаг 7. Начать пользоваться

1. Ответственный за проект отправляет `/inventory`: бот выкладывает посты на две недели и просит отметить, кто что делает и на каком этапе. Так трекер сразу отражает реальное положение дел.
2. `/board` — опубликовать и закрепить доску. Дальше бот обновляет её сам.
3. Команда пишет в чат как обычно: «беру пост на пятницу», «текст готов, отправил клиенту», «клиент ок по тексту», «отдал дизайнеру», «дизайн готов», «показал клиенту с дизайном», «финальный ок», «вышел». Любое действие можно отменить кнопкой или `/undo`.
4. **Мягкий старт.** Первые 14 дней бот только пишет утреннее саммари и ведёт доску, без напоминаний и эскалаций. Срок меняется в `soft_start_days`. За это время станет видно, где бот ошибается, — сообщите, поправим.
5. Спросить бота можно, назвав его по имени: «@имя_бота что по задачам», «@имя_бота что горит», «@имя_бота мои посты». Свободные вопросы он не разбирает (ИИ будет на втором этапе), но эти и подобные фразы понимает как команды.
6. Полный список фраз и команд — `/help`.

## Обновление и резервные копии

**Amvera.** Если подключили GitHub, каждое обновление ветки собирается и запускается само: бот на пару минут замолкает, накопившиеся сообщения он прочитает после запуска — Telegram хранит их сутки. Код обновляет разработчик: он отправляет изменения в ветку, за которой следит Amvera, а владельцу репозитория ничего делать не нужно. Настройки команды и сроков лежат не в репозитории, а в переменной `CONFIG_B64` (или `CONFIG_YAML`): их меняют в Amvera и перезапускают проект. Если загружали файлы вручную, загрузите изменённые файлы заново. Вся память бота лежит в папке Data (`/data`), Amvera сохраняет её копию раз в сутки. Следите за балансом: при нуле проект останавливается, а через 30 дней замораживается. Потерянную базу можно восстановить не полностью: этапы подтянутся из статусов КП, остальное восстановит команда `/inventory`.

**Свой сервер.**

```bash
cd norm_tasker
git pull
docker compose up -d --build
```

Вся память бота — файл `data/tracker.db`. Копируйте его время от времени (например, раз в неделю), вместе с `data/config.yaml`.

## Если что-то не работает

| Что видите | Что делать |
|---|---|
| `doctor` пишет «КП недоступно … не расшарен» | Откройте КП по ссылке для всех («Все, у кого есть ссылка») или поделитесь ею с адресом сервисного аккаунта (шаг 3.6). Адрес виден в первой строке `doctor`. |
| `doctor` пишет «не включён API» | Включите Drive API и Sheets API в проекте Google Cloud (шаг 3.2), подождите минуту. |
| Бот не реагирует на «беру» | Отправьте `/status` и `/id`. Если `/id` отвечает, а «беру» нет — проверьте, что бот администратор и режим приватности выключен (шаг 1.4, 2). Если `/id` не отвечает — бот не запущен или неверный `BOT_TOKEN`: смотрите журнал (Amvera: вкладка «Логи»; Docker: `docker compose logs`). |
| В журнале «Telegram не принял токен бота» | Проверьте `BOT_TOKEN`: без пробелов, кавычек и лишних символов. Токен можно перевыпустить у @BotFather командой `/revoke`. |
| В журнале «Ошибка настроек» | Текст в `CONFIG_YAML` или `config.yaml` не по образцу `config.example.yaml`: журнал называет строку или поле с ошибкой. |
| Бот отвечает только на `/id` | Не указан `chat_id`, или проект не перезапустили после того, как его добавили (шаг 6). Проверка: отправьте `/status`, в ответе должна быть строка «Чат настроен: да». |
| Бот молчит на обычные вопросы вроде «чё по задачам» | Без ИИ бот не разбирает свободные вопросы: он понимает команды и короткие отчёты о постах. Позовите его по имени — «@имя_бота чё по задачам», «@имя_бота что горит», «@имя_бота мои посты» — и он ответит так же, как на команды `/week`, `/today`, `/my`. Фразу, которую бот не узнал, он в ответ на своё имя тоже не оставит без ответа: подскажет команды. Без имени бот в разговоры не вмешивается. |
| Amvera: «Configuration file amvera.yaml or Dockerfile not found» | Amvera не получила файлы из GitHub. Так бывает, если до подключения GitHub в проект загружали файлы вручную (в том числе архив). Создайте новый проект, подключите GitHub первым делом и ничего не загружайте. |
| Amvera: в списке файлов старый коммит, свежие пуши не доходят | Откройте «Репозиторий» → «Подключить GitHub…» → «Удалить» и подключите заново тем же токеном, репозиторием и веткой. Затем нажмите «Пересобрать проект». Какая версия бота запущена, видно в первой строке `/status` («Версия …»). Номер коммита в Amvera не совпадает с GitHub (там свой «Merge»), поэтому сверяйте по версии или по новым файлам в списке. |
| Amvera: сборка падает с `stream error: INTERNAL_ERROR` при загрузке `python:…` | Сбой зеркала образов Amvera. В `Dockerfile` уже используется тег `python:3.12-slim-bookworm`, с ним сборка проходила. Если повторится — пересоберите проект или напишите в поддержку Amvera. |
| Amvera: статус «Ошибка работы приложения» | В первые минуты после запуска это нормально. Если держится дольше 10 минут — откройте «Логи»: там причина. |
| Amvera: журнал полон строк «Telegram пока недоступен» | Проект размещён в зоне «Москва», а оттуда Telegram не открывается. Создайте проект в зоне «Варшава». |
| Amvera: бот остановился | Скорее всего, закончились деньги на балансе: пополните его и запустите проект. Если проект перезапускается сам, тариф Trial тесноват — перейдите на Starter. |
| В журнале «Возможно, бот запущен ещё где-то — жду 10 с» | Пока идёт обновление, минуту работают два экземпляра бота, — это проходит само. Если строка не исчезает, с этим токеном запущен ещё один бот (старый сервер, компьютер): остановите его. |
| Доска не закрепляется | Дайте боту право «Закрепление сообщений». |
| Реакции 👍 не ставятся | В группе ограничены реакции. Бот в таком случае пишет «👍 Записал.» текстом — ничего делать не нужно. |
| «Мог что-то пропустить» после простоя | Telegram хранит сообщения для бота 24 часа. Сверьте доску (`/board`) и поправьте этапы. |
| Бот принял заметку за пост | Ответьте на его сообщение «не пост». Заметки лучше начинать с «NB:» — такие строки в КП бот пропускает. |
| Пост не тот | Нажмите «Отменить» под ответом бота или `/undo`. |

Проблему, которой здесь нет, можно диагностировать по журналу: в Amvera — вкладка «Логи», в Docker — `docker compose logs --tail 200`. Приложите вывод, когда будете писать разработчику (токен и ключи в журнал не попадают).

## Как проверить КП без запуска бота

Если хочется убедиться, что бот правильно разбирает таблицу и считает сроки:

1. В Google Таблицах: **Файл → Скачать → Microsoft Excel (.xlsx).**
2. Выполните (нужен Python 3.12 и `pip install .`):

   ```bash
   python -m norm_tasker parse выгрузка.xlsx --weeks 3
   ```

   Команда покажет посты, рубрики, статусы, этапы и сроки. Файл остаётся на вашем компьютере.
